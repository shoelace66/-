# AI Roleplay Chat v2.3.0

本版本重做事件召回链路，目标是在不引入向量库和数据库迁移的前提下，提高确定性并严格控制 roleplay 长对话的模型费用。

## 主要更新

- 将“jieba 本地分词 + 每轮 LLM 关键词提取 + BFS”替换为固定的 `L0 → PLAN → JUDGE` 状态机。
- L0 只匹配事件已有的完整 `keywords/theme`、物品/设定关系键，并以确定性权重进行一跳、二跳图扩展；不扫描事件描述或来源对话。
- 根据候选质量自适应产生 0、1 或 2 次额外请求：明确命中完全本地完成，只有歧义时才调用模型。
- 新增可选的独立事件召回 LLM Profile。未配置时复用主模型；配置后若调用失败，只退化到本地结果，不再自动切换昂贵主模型。
- 引入每轮独占的实际 HTTP POST 预算。超时、网络失败与 404/405 兼容端点探测均计入最多 2 次的上限，成功端点会被缓存。
- PLAN/JUDGE 采用严格 JSON 和临时 ID 白名单；模型只能选择结构化目录或冻结候选，不能生成、修改或回写记忆。
- 移除 `jieba_flutter` 以及约 6.1 MB 的本地词典资源，减小安装包和初始化负担。

## 调用策略

| 场景 | 额外 POST | 行为 |
|---|---:|---|
| 无可用冷记忆，或没有结构化连续性 | 0 | 不追加关联事件 |
| keyword/relation 强命中且候选明确 | 0 | 采用本地排序 |
| PLAN 后候选清晰 | 1 | 采用 PLAN 约束后的本地结果 |
| PLAN 后仍有歧义且预算充足 | 2 | JUDGE 从最多 12 个候选中选择最多 5 个 |
| 模型超时、响应无效或预算耗尽 | 0–2 | 保留已得到的本地结果，正文对话继续 |

正文对话模型调用不计入上述事件召回预算。

## 数据与升级兼容

- 应用版本：`2.3.0`（versionCode `7`）。
- SQLite 保持 v3，不新增表、不要求迁移现有事件节点。
- 旧 Provider 配置没有 `memoryRecallLlm` 时会正常读取，并自动沿用主 LLM。
- 完整备份格式不变；升级前仍建议先在应用内导出备份。

## 已知限制

- V1 的召回上限取决于正文模型此前写入的结构化关键词、主题和关系键；漏标与别名不一致不会通过分词或模糊字符匹配补救。
- 不使用向量、Embedding、FTS、BM25、拼音、编辑距离、同义词扩展或故事内时间推断。
- 独立召回模型的费用未加入现有会话用量估算页面；本版本通过请求次数、输入长度与输出 Token 上限控制成本。
